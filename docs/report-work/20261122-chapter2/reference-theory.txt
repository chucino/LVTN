 2.1 Tổng quan về hệ thống Freelancer Marketplace 
Hệ thống kết nối nhân lực tự do (Freelance Marketplace) được xây dựng nhằm thiết 
lập một môi trường trung gian kỹ thuật số hiện đại, tối ưu hóa sự tương tác giữa Nhà 
tuyển dụng (Clients) và Người làm nghề tự do (Freelancers). Về mặt vận hành, hệ thống 
đóng vai trò là một nền tảng quản lý dự án khép kín, cho phép người dùng thực hiện toàn 
bộ quy trình từ đăng tải yêu cầu, đấu thầu dự án (Bidding), đến giai đoạn trao đổi trực 
tuyến và nghiệm thu sản phẩm. 
Để đảm bảo tính bảo mật, hiệu năng và khả năng mở rộng, hệ thống được phát triển 
dựa trên kiến trúc phân lớp hiện đại. Ở phía Backend, hệ thống sử dụng framework Java 
Spring Boot kết hợp với Spring Data JPA để quản lý thực thể và tương tác với cơ sở dữ 
liệu quan hệ PostgreSQL, giúp đảm bảo tính toàn vẹn dữ liệu cho các giao dịch tài chính 
phức tạp. Vấn đề an toàn thông tin và phân quyền người dùng được kiểm soát chặt chẽ 
thông qua Spring Security. Ở phía Frontend, ứng dụng được xây dựng bằng thư viện 
React kết hợp với Redux để quản lý trạng thái (state) toàn cục một cách hiệu quả. Việc 
giao tiếp giữa hai phía được thực hiện qua Axios để gọi các RESTful API. Về mặt giao 
diện, hệ thống tận dụng sức mạnh của Material UI (MUI) và Tailwind CSS để tạo ra một 
trải nghiệm người dùng (UX/UI) tinh tế, nhất quán và có khả năng hiển thị tương thích 
trên nhiều thiết bị (Responsive Design). Sự kết hợp giữa các công nghệ mạnh mẽ này 
không chỉ giúp hệ thống vận hành ổn định mà còn tạo nền tảng vững chắc để triển khai

 2.2 Ngôn ngữ lập trình Java 
 
 
Hình 2-1: Logo Java (Nguồn: https://logos-world.net/java-logo/) 
Java là ngôn ngữ lập trình hướng đối tượng (OOP) đa năng, nổi bật với tính độc lập nền 
tảng cao nhờ cơ chế máy ảo Java (JVM). Trong dự án này, Java được lựa chọn làm nền 
tảng chính cho phần backend bởi khả năng xử lý đa luồng vượt trội, hệ thống kiểu dữ 
liệu chặt chẽ (strongly typed) cùng hệ sinh thái và cộng đồng hỗ trợ cực kỳ phong phú. 
Những đặc điểm này đặc biệt phù hợp khi xây dựng các nghiệp vụ phức tạp của một sàn 
giao dịch freelancer, chẳng hạn như quản lý quy trình chào thầu, theo dõi tiến độ dự án  
hay tính toán doanh thu, hoa hồng theo thời gian thực. 
Những điểm mạnh nổi bật của Java trong hệ thống: 
- Bảo mật vượt trội Java cung cấp môi trường thực thi an toàn (sandbox) ngay từ cấp 
độ máy ảo, giúp ngăn chặn hiệu quả các mã độc hoặc hành vi xâm nhập trái phép, 
đảm bảo an toàn cho dữ liệu người dùng và các giao dịch tài chính trên nền tảng. 
- Khả năng xử lý đa luồng mạnh mẽ Đây chính là thế mạnh lớn nhất của Java. Với cơ 
chế thread, concurrency API hiện đại (ExecutorService, Fork/Join, 
CompletableFuture, v.v.), hệ thống có thể xử lý đồng thời hàng nghìn yêu cầu từ 
freelancer và client mà không bị tắc nghẽn – tình huống thường gặp khi nhiều người 
cùng chào thầu một dự án hấp dẫn hoặc thực hiện thanh toán cùng lúc. 
- Tính độc lập nền tảng – “Write Once, Run Anywhere ” Nhờ JVM, mã nguồn Java 
chỉ cần biên dịch một lần và có thể chạy trên mọi môi trường (Linux, Windows, 
macOS, các nền tảng cloud như AWS, GCP, Azure) mà không cần chỉnh sửa. Điều 
này giúp đội ngũ triển khai linh hoạt, dễ dàng mở rộng hạ tầng và giảm thiểu chi phí 
bảo trì khi hệ thống phát triển quy mô.

 2.3 Framework Spring Boot 
 
 
Hình 2-2: Logo SpringBoot (Nguồn: sping-logo) 
Spring Boot là một module quan trọng trong hệ sinh thái Spring Framework, được thiết 
kế nhằm đơn giản hóa đáng kể quá trình phát triển, cấu hình và triển khai ứng dụng Java. 
Với nguyên tắc cốt lõi “Convention over Configuration” (Ưu tiên quy ước thay vì cấ u 
hình thủ công), Spring Boot loại bỏ gần như toàn bộ các file XML phức tạp và mã 
boilerplate truyền thống, thay vào đó cung cấp các Spring Boot Starters  – những gói 
khởi tạo sẵn chứa đầy đủ các dependency cần thiết cho từng loại ứng dụng (Web, 
Security, Data JPA, Messaging, v.v.). 
Trong dự án sàn giao dịch freelancer này, việc lựa chọn Spring Boot mang lại lợi thế lớn 
về tốc độ triển khai và khả năng bảo trì lâu dài, đặc biệt khi xây dựng các API RESTful, 
xử lý giao dịch thời gian thực, quản lý người dùng đa vai trò và tích hợp các dịch vụ bên 
thứ ba. 
Những điểm mạnh nổi bật của Spring Boot: 
- Tăng tốc độ phát triển vượt trội: Nhờ hệ thống Starters phong phú, lập trình viên 
chỉ cần thêm một dependency duy nhất (ví dụ: spring -boot-starter-web, spring-
boot-starter-data-jpa) là đã có thể khởi động ngay một ứng dụng web hoàn chỉnh 
với Tomcat nhúng, Jackson JSON, Hibernate, v.v. – giúp rút ngắn đáng kể thời 
gian từ ý tưởng đến MVP. 
- Quản lý dependency thông minh và tự động : Spring Boot cung cấp Bill of 
Materials (BOM) – một danh sách phiên bản dependency đã được kiểm chứng 
tương thích lẫn nhau. Điều này gần như loại bỏ hoàn toàn xung đột phiên bản 
(dependency hell), đảm bảo hệ thống luôn ổn định ngay cả khi mở rộng quy mô 
hoặc nâng cấp thư viện. 
- Tích hợp sẵn công cụ giám sát và vận hành : Với Spring Boot Actuator, hệ thống

 2.4 Spring Data JPA và Hibernate 
 
Hình 2-3: Logo JPA (Nguồn: velog.io) 
Spring Data JPA là module quan trọng thuộc Spring Framework, được thiết kế nhằm 
đơn giản hóa tối đa việc tương tác với cơ sở dữ liệu quan hệ (RDBMS) thông qua kỹ 
thuật Object-Relational Mapping (ORM). Thay vì phải viết các câu lệnh SQL thủ công, 
lập trình viên chỉ cần định nghĩa các entity Java và repository interface, sau đó Spring 
Data JPA sẽ tự động sinh ra các truy vấn cần thiết. Điều này giúp mã nguồn trở nên sạch 
sẽ, dễ đọc, dễ bảo trì và giảm đáng kể nguy cơ lỗi cú pháp SQL. 
Trong dự án, Hibernate được chọn làm implementation mặc định của JPA, mang lại hiệu 
suất cao nhờ các cơ chế tối ưu hóa truy vấn, quản lý transaction và caching thông minh. 
Spring Data JPA kết hợp hoàn hảo với Spring Boot, cho phép khởi tạo nhanh repository 
với các phương thức CRUD cơ bản chỉ bằng cách khai báo interface (không cần 
implement). 
Những điểm mạnh nổi bật của Spring Data JPA trong hệ thống: 
- Tăng tốc độ phát triển và giảm thiểu lỗi : Với các phương thức truy vấn tự động 
(query methods) như findByEmail, findBySkillsContaining, hoặc @Query

 2.5 Spring Security 
 
Hình 2-4: Logo Spring Security (Nguồn: alekya3 ) 
Spring Security là một trong những framework bảo mật mạnh mẽ và phổ biến nhất trong 
hệ sinh thái Spring, cung cấp giải pháp toàn diện cho cả xác thực (Authentication) và 
phân quyền (Authorization). Trong dự án sàn giao dịch freelancer, Spring Security được 
lựa chọn làm nền tảng bảo mật cốt lõi, đảm bảo kiểm soát chặt chẽ truy cập dựa trên vai 
trò người dùng (Role -Based Access Control – RBAC), bảo vệ các API endpoint nhạy 
cảm và mã hóa thông tin cá nhân, đặc biệt là mật khẩu và dữ liệu giao dịch. 
Framework này tích hợp mượt mà với Spring Boot, hỗ trợ các cơ chế xác thực hiện đại 
như JWT (JSON Web Token) cho API stateless, OAuth2/OpenID Connect cho đăng 
nhập xã hội (Google, GitHub…), hoặc kết hợp với form login truyền thống. Nhờ đó, hệ 
thống có thể an toàn xử lý các quy trình như đăng ký, đăng nhập, chào thầu, thanh toán 
và quản lý dự án mà không lo rò rỉ thông tin.

Những điểm mạnh nổi bật của PostgreSQL trong hệ thống: 
- Hỗ trợ kiểu dữ liệu phong phú và linh hoạt : Ngoài các kiểu dữ liệu truyền thống 
(số, chuỗi, ngày tháng), PostgreSQL xuất sắc trong việc xử lý dữ liệu phi cấu trúc 
như JSON và JSONB (binary JSON). Điều này cho phép lưu trữ thông tin tùy 
biến một cách tự nhiên và hiệu quả, ví dụ: 
+ Danh sách kỹ năng của Freelancer dưới dạng mảng JSONB. 
+ Portfolio, chứng chỉ, hoặc mô tả dự án với cấu trúc động. 
+ Dữ liệu metadata của dự án (tags, attachments). Nhờ đó, hệ thống 
không cần tạo quá nhiều bảng phụ, giúp schema đơn giản hơn và truy 
vấn nhanh hơn. 
- Toàn vẹn dữ liệu nghiêm ngặt và đáng tin cậy: PostgreSQL áp dụng các ràng buộc 
(constraints) mạnh mẽ ở cấp độ cơ sở dữ liệu: 
+ NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY (với ON 
DELETE/UPDATE CASCADE/RESTRICT). 
+ CHECK constraints để kiểm tra logic nghiệp vụ (ví dụ: ngân sách dự án 
phải > 0). 
+ EXCLUSION constraints cho các trường hợp phức tạp. Những cơ chế này 
đảm bảo dữ liệu luôn nhất quán, ngăn chặn dữ liệu rác, trùng lặp hoặc vi 
phạm quy tắc kinh doanh ngay từ tầng database – giảm thiểu lỗi ứng dụng 
và tăng độ tin cậy tổng thể. 
- Hiệu suất cao với truy vấn phức tạp : PostgreSQL hỗ trợ full -text search

 2.11 Mô hình MVC 
 
 
Hình 2-10: Mô hình MVC (Nguồn: Vietnix) 
Mô hình MVC là một trong những kiến trúc thiết kế (design pattern) cổ điển và được 
sử dụng rộng rãi nhất trong phát triển ứng dụng web, desktop và mobile. Nó được giới 
thiệu lần đầu vào những năm 1970 trong ngôn ngữ Smalltalk, sau đó trở thành chuẩn 
mực cho nhiều framework hiện đại như Spring MVC (Java), ASP.NET MVC (C#), 
Ruby on Rails, Laravel (PHP), Django (Python), và cả các ứng dụng frontend như 
Angular. 
MVC chia ứng dụng thành ba thành phần chính, mỗi thành phần chịu trách nhiệm một 
phần riêng biệt, giúp mã nguồn được tổ chức rõ ràng, dễ bảo trì, dễ mở rộng và dễ kiểm 
thử. 
Các thành phần chính của mô hình MVC: 
Model (Mô hình) Đại diện cho dữ liệu và logic nghiệp vụ của ứng dụng. Model 
chịu trách nhiệm: 
- Quản lý dữ liệu (lưu trữ, truy xuất, cập nhật). 
- Thực hiện các quy tắc kinh doanh (business rules). 
- Không quan tâm đến cách dữ liệu được hiển thị hoặc tương tác với người 
dùng. Model thường tương tác trực tiếp với cơ sở dữ liệu (qua ORM như 
Hibernate, Entity Framework) hoặc các dịch vụ bên ngoài. 
View (Giao diện) Chịu trách nhiệm hiển thị dữ liệu cho người dùng. View: 
- Nhận dữ liệu từ Controller (hoặc Model). 
- Chuyển đổi dữ liệu thành định dạng mà người dùng có thể nhìn thấy 
(HTML, JSON, giao diện đồ họa). 
- Không chứa logic nghiệp vụ, chỉ tập trung vào trình bày (presentation 
logic). View thường là các template (JSP, Thymeleaf, Razor, Blade) hoặc 
component trong frontend (React, Vue, Angular). 


PAGE 87
 
 
CBHD: TS. Nguyễn Công Danh  
 53  
Controller (Bộ điều khiển) Đóng vai trò trung gian, xử lý các yêu cầu từ người dùng 
và điều phối luồng dữ liệu giữa Model và View. Controller: 
- Nhận request từ client (qua URL, form submit, API call). 
- Xử lý input, gọi Model để thực hiện nghiệp vụ. 
- Lấy kết quả từ Model và chuyển cho View để hiển thị. 
- Không chứa logic hiển thị hay logic lưu trữ dữ liệu. 
Luồng hoạt động cơ bản của MVC: 
1. Người dùng gửi request (click button, truy cập URL). 
2. Controller nhận request và xử lý. 
3. Controller gọi Model để thực hiện logic nghiệp vụ và lấy dữ liệu. 
4. Model trả kết quả cho Controller. 
5. Controller chọn View phù hợp và truyền dữ liệu vào View. 
6. View render dữ liệu thành giao diện và gửi response về cho người dùng. 
Lợi ích chính của mô hình MVC: 
- Tách biệt trách nhiệm (Separation of Concerns): Mỗi thành phần chỉ làm một 
việc, giúp mã nguồn sạch sẽ, dễ đọc và dễ bảo trì. 
- Dễ kiểm thử: Model, View và Controller có thể được unit test độc lập. 
- Tái sử dụng cao: Model có thể được dùng lại cho nhiều View khác nhau (ví dụ: 
API JSON cho mobile và HTML cho web). 
- Hỗ trợ phát triển song song: Nhóm frontend (View) và backend (Model + 
Controller) có thể làm việc độc lập. 
- Dễ mở rộng và bảo trì: Khi thay đổi giao diện (View) hoặc logic nghiệp vụ 
(Model), không ảnh hưởng lớn đến các phần còn lại.

Hình 2-11: Logo RestAPI (Nguồn:capellasolutions ) 
RESTful API (Representational State Transfer) là một phong cách kiến trúc thiết kế 
dịch vụ web, dựa trên các nguyên tắc được định nghĩa rõ ràng nhằm tạo ra các giao 
diện lập trình ứng dụng dễ hiểu, dễ sử dụng và dễ mở rộng. Kiến trúc này tận dụng tối 
đa các đặc tính của giao thức HTTP để xây dựng các dịch vụ client-server phân tách, 
stateless và có khả năng cache. 
Các nguyên tắc cốt lõi của RESTful API: 
- Phân tách rõ ràng giữa client và server Client chịu trách nhiệm giao diện và trải 
nghiệm người dùng, server chịu trách nhiệm xử lý logic nghiệp vụ và lưu trữ dữ 
liệu. Sự tách biệt này cho phép phát triển, bảo trì và mở rộng độc lập hai thành 
phần. 
- Stateless (không lưu trạng thái) Mỗi request từ client đến server phải chứa đầy 
đủ thông tin cần thiết để xử lý, không phụ thuộc vào trạng thái của các request 
trước đó. Server không lưu trữ thông tin phiên của client, giúp hệ thống dễ dàng 
mở rộng quy mô ngang. 
- Cacheable Các phản hồi từ server có thể được đánh dấu là có thể lưu cache. 
Điều này cho phép client, proxy hoặc CDN lưu trữ tạm thời dữ liệu để giảm tải 
cho server và cải thiện tốc độ phản hồi. 
- Uniform Interface (giao diện thống nhất) Đây là nguyên tắc quan trọng nhất, 
bao gồm bốn đặc điểm: 
+ Tài nguyên được xác định duy nhất qua URI. 
+ Thao tác trên tài nguyên thông qua biểu diễn (representation) của chúng. 
+ Các thông điệp tự mô tả đầy đủ (self-descriptive). 
+ Khả năng sử dụng hypermedia để dẫn dắt trạng thái ứng dụng 
(HATEOAS – dù không phải lúc nào cũng được triển khai đầy đủ). 
- Layered System Hệ thống có thể bao gồm nhiều lớp trung gian (load balancer, 
proxy, gateway) mà client không cần biết đến. Client chỉ tương tác với điểm 
cuối cùng trong chuỗi.

 2.13 Axios 
 
Hình 2-12: Logo Axios (Nguồn: wikimedia) 
Axios là một thư viện HTTP client dựa trên Promise, được thiết kế để thực hiện các 
yêu cầu mạng (HTTP requests) một cách đơn giản, hiệu quả và đáng tin cậy trong cả 
môi trường trình duyệt (browser) và Node.js. Được phát triển từ năm 2014, Axios 
nhanh chóng trở thành lựa chọn hàng đầu cho các lập trình viên JavaScript/TypeScript 
khi xây dựng ứng dụng frontend (đặc biệt với React, Vue, Angular) hoặc các script 
phía server. 
Axios nổi bật nhờ cú pháp sạch sẽ, hỗ trợ đầy đủ các tính năng hiện đại của HTTP, và 
tích hợp mượt mà với các thư viện quản lý trạng thái cũng như các framework 
frontend. Nó được sử dụng rộng rãi trong các dự án thực tế để giao tiếp với RESTful 
API, GraphQL endpoint hoặc bất kỳ dịch vụ web nào. 
Những điểm mạnh nổi bật của Axios: 
- Cú pháp đơn giản và dễ đọc: Axios sử dụng API dựa trên Promise với cấu trúc 
rõ ràng, dễ hiểu hơn so với Fetch API gốc của trình duyệt. Các phương thức như 
get, post, put, delete được thiết kế trực quan, hỗ trợ truyền config object linh 
hoạt. 
- Hỗ trợ Promise và async/await hoàn hảo: Mọi request đều trả về Promise, cho 
phép sử dụng cú pháp async/await hiện đại, giúp code trở nên dễ đọc và dễ xử lý 
luồng bất đồng bộ. 
- Interceptor mạnh mẽ: Axios cung cấp request và response interceptors – cơ chế 
chặn và can thiệp vào mọi request/response đi qua. Điều này rất hữu ích để: 
+ Thêm token xác thực (JWT, Bearer) tự động vào header. 
+ Xử lý lỗi toàn cục (ví dụ: refresh token khi 401 Unauthorized). 
+ Log request/response trong quá trình phát triển. 
+ Thay đổi data trước khi gửi hoặc sau khi nhận. 
- Xử lý lỗi tập trung và chi tiết: Axios có cơ chế xử lý lỗi rõ ràng với object error 
chứa đầy đủ thông tin: status code, response data, request config, message…

Điều này giúp lập trình viên dễ dàng xây dựng hệ thống thông báo lỗi thân thiện

- Hỗ trợ transform dữ liệu tự động: Tự động parse JSON response thành object

 2.14 Stripe API 
 
Hình 2-13: Logo Stripe (Nguồn: wikimedia) 
Stripe API là bộ giao diện lập trình ứng dụng (API) toàn diện do Stripe cung cấp, được 
thiết kế để tích hợp xử lý thanh toán trực tuyến, quản lý hóa đơn, đăng ký định kỳ 
(subscriptions), chuyển khoản và các dịch vụ tài chính khác vào ứng dụng web hoặc 
mobile. Đây là một trong những hệ thống thanh toán phổ biến nhất dành cho developer, 
nổi tiếng với tài liệu chi tiết, thiết kế RESTful chuẩn mực và khả năng tùy chỉnh cao. 
Stripe API được tổ chức xung quanh kiến trúc REST, sử dụng các URL tài nguyên rõ 
ràng, body request dạng form-encoded, response dạng JSON, cùng các mã trạng thái 
HTTP chuẩn, phương thức xác thực và verb HTTP thông thường. API được chia thành 
hai namespace chính (v1 và v2), với v2 mang đến các thiết kế hiện đại hơn cho một số

endpoint. 
Các nguyên tắc và đặc điểm cốt lõi của Stripe API: 
- RESTful và resource-oriented: Mọi thứ trong Stripe đều được coi là object (tài 
nguyên), như Customer, PaymentIntent, Charge, Subscription, Product, Price… 
Các endpoint có cấu trúc dự đoán được, dễ hiểu và nhất quán (ví dụ: 
/v1/payment_intents, /v1/customers). 
- Stateless và idempotent: Mỗi request độc lập, không phụ thuộc trạng thái trước 
đó. Nhiều hoạt động hỗ trợ idempotency key để tránh trùng lặp (ví dụ: tạo thanh 
toán nhiều lần mà không charge double). 
- Test mode và Live mode riêng biệt: Sử dụng API key khác nhau: 
+ Publishable key (pk_...) cho client-side (an toàn để expose). 
+ Secret key (sk_...) cho server-side (phải giữ bí mật). 
+ Restricted key để giới hạn quyền truy cập. Test mode sử dụng dữ liệu giả 
lập, không ảnh hưởng đến tiền thật. 
- Xác thực và bảo mật cao Tất cả request đều yêu cầu authentication qua API key. 
Stripe tuân thủ PCI DSS Level 1, hỗ trợ tokenization để không lưu thông tin thẻ 
nhạy cảm trên server của bạn. 
Các tính năng chính nổi bật của Stripe API: 
- Xử lý thanh toán linh hoạt: Hỗ trợ hàng trăm phương thức thanh toán toàn cầu 
(thẻ tín dụng/debit, digital wallets như Apple Pay/Google Pay, chuyển khoản 
ngân hàng địa phương như iDEAL, SEPA, Alipay…). 
- PaymentIntents & PaymentMethods: Mô hình hiện đại để xử lý thanh toán đa 
bước (3D Secure, xác thực SCA), hỗ trợ dynamic 3DS và các flow 
asynchronous. 
- Subscriptions & Billing: Quản lý gói đăng ký định kỳ, hóa đơn tự động, thử 
nghiệm miễn phí, nâng cấp/hạ cấp gói, xử lý thất bại thanh toán. 
- Invoicing & Revenue Recognition: Tạo hóa đơn, gửi tự động, theo dõi thanh 
toán, hỗ trợ thuế tự động. 
- Fraud Prevention & Radar: Công cụ machine learning tích hợp để phát hiện gian 
lận, chặn giao dịch rủi ro cao. 
- Payouts & Connect: Chuyển tiền cho người dùng (như freelancer), hỗ trợ 
marketplace (Stripe Connect) với split payment, escrow. 
- Webhooks: Hệ thống thông báo sự kiện realtime (payment succeeded, 
subscription updated, charge failed…) để ứng dụng phản hồi tức thì.

 2.14 Cloudinary 
 
Hình 2-14: Logo Cloudinary (Nguồn: wikimedia) 
Cloudinary là một dịch vụ đám mây (cloud-based) chuyên biệt cho việc quản lý, tối ưu 
hóa, chuyển đổi và phân phối hình ảnh cũng như video. Được thiết kế dành riêng cho 
các nhà phát triển web và ứng dụng di động, Cloudinary giúp loại bỏ hoàn toàn những 
phức tạp liên quan đến việc xử lý media trên server, đồng thời mang lại hiệu suất cao, 
khả năng tùy chỉnh mạnh mẽ và trải nghiệm người dùng tốt nhất trên mọi thiết bị. 
Cloudinary hoạt động theo mô hình SaaS (Software as a Service), cung cấp API 
RESTful và SDK cho hầu hết các ngôn ngữ lập trình phổ biến (JavaScript, React, 
Node.js, Java, Python, PHP, Ruby, .NET, v.v.). Nó kết hợp lưu trữ, xử lý động (on-the-
fly transformation), tối ưu hóa tự động và CDN toàn cầu để phân phối nội dung nhanh 
chóng. 
Các nguyên tắc và đặc điểm cốt lõi của Cloudinary: 
- Media as a Service: Hình ảnh và video được coi là tài nguyên có thể truy cập 
qua URL duy nhất, với mọi thao tác xử lý được thực hiện động thông qua tham 
số trong URL (không cần tạo file vật lý mới). 
- On-the-fly transformation: Tất cả các thay đổi (resize, crop, format conversion, 
watermark, face detection, compression, v.v.) đều được thực hiện thời gian thực 
khi request, không cần lưu trữ nhiều phiên bản khác nhau của cùng một file. 
- Tự động tối ưu hóa: Cloudinary tự động chọn định dạng tốt nhất (WebP, AVIF, 
JPEG-XL cho hình ảnh; HLS/DASH cho video) dựa trên trình duyệt và thiết bị 
của người dùng, đồng thời nén chất lượng cao mà không làm giảm trải nghiệm 
hình ảnh. 
- CDN tích hợp toàn cầu: Sử dụng mạng phân phối nội dung (CDN) với hàng
